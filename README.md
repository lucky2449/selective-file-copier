# 파일모아 · FileCopier Web

숫자·파일명 목록을 기준으로 원본 폴더에서 필요한 파일만 찾아 모으는 웹 도구입니다. 설치, 로그인, 비밀번호 없이 사용할 수 있으며 파일 내용은 사용자의 브라우저에서 처리합니다.

**기본 사이트:** [파일모아 열기](https://lucky2449.github.io/selective-file-copier/)

## 주요 기능

- 원본 폴더와 하위 폴더 검색
- 숫자·파일명·확장자를 제외한 이름·상대 경로·Windows 경로 입력
- TXT 목록 불러오기와 선택한 파일에서 이름 가져오기
- 확장자 필터, JPG 이름으로 같은 이름의 RAW 파일 찾기
- 중복 후보 직접 선택, 결과 개별·전체 선택
- 기본은 파일별 일반 다운로드, 지원 브라우저에서는 지정 폴더 직접 복사
- 파일명 충돌 시 `_1`, `_2` 추가, 동일 원본 중복 복사 방지
- 진행 상황·작업 기록·취소 기능과 반응형 검은색 테마

## 사용 방법

1. **원본 폴더 선택**으로 파일이 있는 폴더를 고릅니다. 하위 폴더도 포함됩니다.
2. 찾을 목록을 붙여 넣거나 **TXT 불러오기**, **파일에서 이름 가져오기**를 사용합니다.
3. 확장자를 정하고 **파일 찾기**를 누릅니다.
4. 중복 후보가 있으면 결과에서 원하는 파일을 지정합니다.
5. 저장 위치를 지정하지 않으면 **선택 파일 다운로드**로 각 파일을 일반 다운로드합니다. 폴더 접근을 요청하지 않으며 새 폴더나 ZIP은 만들지 않습니다. 저장 위치는 브라우저 설정을 따릅니다.
6. 특정 폴더에 저장하려면 지원 브라우저에서 **저장 폴더 선택 (선택 사항)** 후 **선택 파일 복사**를 누르세요. 모든 원본 선택 방식에서 저장 폴더 안에 날짜와 UUID가 포함된 새 결과 폴더를 만들어 복사합니다. **일반 다운로드 사용**으로 기본 방식으로 돌아갈 수 있습니다.
7. 직접 복사 모드의 폴더 접근이 차단되면 기본 **원본 폴더 선택** 버튼을 사용하세요. 기본 버튼은 보호 폴더 접근 API를 호출하지 않는 일반 파일 선택창입니다. ZIP이 필요할 때만 별도의 **ZIP 다운로드 (대체)**를 누릅니다.

여러 파일을 다운로드할 때 브라우저에서 **여러 파일 다운로드 허용**을 요청할 수 있습니다. 앱에 표시되는 숫자는 브라우저에 전달한 다운로드 요청 수이며 실제 저장 완료를 뜻하지 않습니다. 저장 위치와 완료 여부는 브라우저 다운로드 목록에서 확인하세요.

### 입력과 검색 규칙

```text
323, 2134
DSC00323.jpg
IMG_001
"photo, summer.jpg"
"my photo.jpg"
C:\photos\day1\DSC00323.jpg
```

| 입력                        | 동작                                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `323`                       | 파일명 끝의 숫자 전체를 비교해 `DSC00323.jpg`를 찾습니다. `23`으로 해당 파일을 찾지는 않습니다.               |
| `DSC00323.jpg`              | 파일명을 비교하며 대소문자는 구분하지 않습니다.                                                               |
| `IMG_001`                   | 확장자를 제외한 이름을 비교합니다.                                                                            |
| `IMG_001.jpg` + `.cr3` 필터 | 같은 이름의 `IMG_001.cr3`를 찾습니다.                                                                         |
| `day1/DSC00323.jpg`         | 선택한 폴더 안의 경로를 비교합니다. Windows 경로도 입력할 수 있지만 선택하지 않은 폴더에는 접근하지 않습니다. |

‘모든 파일’에서는 확장자를 입력한 경우 해당 확장자까지 일치해야 찾습니다. 예를 들어 JPG가 없다고 같은 이름의 XMP·MP4·RAW를 대신 선택하지 않습니다. 다른 형식을 찾으려면 복사할 확장자 필터를 명시적으로 선택하세요. ‘파일에서 이름 가져오기’도 확장자를 포함한 이름을 가져옵니다.

목록은 쉼표·세미콜론·줄바꿈으로 구분합니다. 숫자는 공백과 `/`로도 나눌 수 있습니다. 구분자가 포함된 파일명은 큰따옴표로 감싸세요. 숫자 선행 0은 무시하며, 중복 후보는 자동으로 임의 선택하지 않습니다.

TXT는 UTF-8을 먼저 읽고 실패하면 EUC-KR로 해석합니다. TXT 파일은 5MB 이하, 검색 목록은 한 번에 최대 20,000개 항목을 지원합니다.

## 브라우저 호환성과 저장 방식

| 기능               | 사용 API와 동작                                                                                                                                |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 원본 폴더 읽기     | 기본은 일반 파일 선택창 `input[type=file][webkitdirectory]`입니다. 별도 직접 복사 모드에서만 `showDirectoryPicker()`로 원본 핸들을 받습니다.   |
| 기본 일반 다운로드 | 각 원본 `File`을 `blob:` URL과 `<a download>`로 내려받습니다. 폴더 선택 API나 ZIP 생성은 사용하지 않습니다.                                    |
| 폴더 직접 복사     | `showDirectoryPicker()`가 있는 환경에서 저장 폴더를 선택해 복사합니다. 항상 새 결과 하위 폴더로 격리합니다. 데스크톱 Chrome·Edge를 권장합니다. |
| ZIP 다운로드       | 별도 버튼을 눌렀을 때 ZIP을 생성해 브라우저 다운로드로 저장합니다.                                                                             |

직접 복사는 원본 핸들이 있는 경우 `isSameEntry()`와 `resolve()`로 원본과 같은 폴더 및 원본 하위 폴더를 저장 대상으로 차단합니다. 검사 실패 시에도 복사를 중단합니다. 원본 핸들이 없어도 저장 폴더를 선택할 수 있으나 동일 여부와 포함 관계를 확인할 수 없습니다. 모든 모드에서 날짜·UUID를 포함한 새 결과 폴더에만 복사하며, 생성 직후 기존 항목이 발견되면 중단합니다. 일반 다운로드 이후에도 저장 폴더를 선택할 수 있습니다.

브라우저는 시스템 폴더나 다운로드 폴더 전체 등 보호 대상 폴더의 직접 접근을 차단할 수 있습니다. 원본 읽기가 차단되면 일반 파일 선택창을, 저장 폴더 접근이 차단되면 다른 폴더 또는 일반 다운로드를 사용하세요. 직접 복사 실패 시 다운로드나 ZIP으로 자동 전환하지 않습니다.

일반 다운로드는 브라우저의 저장 위치 설정, 저장 전 확인 설정과 다중 다운로드 허용 정책을 따릅니다. 기본 다운로드 폴더에 이미 있는 파일은 앱이 검사할 수 없으며 실제 충돌 처리는 브라우저가 결정합니다. 한 작업 내 동일 파일명은 `_1`, `_2`를 붙여 요청합니다.

## 파일 처리와 제한

- 파일 업로드·검색을 위한 별도 서버 API, 데이터베이스, 로그인 기능이 없습니다. 호스팅 서버는 HTML·CSS·JavaScript를 제공합니다.
- 파일 검색, TXT 해석, 복사와 ZIP 생성은 브라우저에서 수행하며 파일 내용은 서버로 전송하지 않습니다.
- 원본은 변경하지 않습니다. 일반 다운로드는 파일별로 저장하고 직접 복사는 새 결과 폴더에, ZIP은 압축 파일 최상위에 모읍니다. 원본 하위 폴더 구조는 재현하지 않습니다.
- 직접 복사는 파일 내용을 보존하지만 수정 시각 등 운영체제 메타데이터까지 보존하지는 않습니다.
- ZIP은 **무압축**이며 ZIP64를 지원하지 않습니다. ZIP당 4GB 미만·65,535개 이하로 나눠 저장하세요.
- ZIP 일반 다운로드는 메모리 사용을 제한하기 위해 예상 ZIP 크기를 512MB 이하로 제한합니다. 큰 작업은 폴더 직접 복사를 사용하세요.
- 일반 다운로드의 취소는 추가 요청만 중단하며, 이미 요청한 파일은 브라우저에서 취소해야 합니다. 취소 전에 이미 복사된 파일은 남습니다. 실패·취소 시 쓰기를 중단하고 작업 기록에 표시합니다. 미완성 결과 파일이나 폴더가 남더라도 자동 삭제하지 않습니다.

## 로컬 실행

웹 실행에 npm 설치나 빌드는 필요하지 않습니다. Python 3가 있다면 저장소 루트에서 실행합니다.

```powershell
python -m http.server 8080 --directory docs --bind 127.0.0.1
```

브라우저에서 [http://localhost:8080](http://localhost:8080)을 엽니다. HTML을 더블클릭하는 대신 HTTP 서버를 사용하세요.

개발 중에는 `--directory sites/filecopier-web/dist`로 원본을 바로 확인할 수 있습니다.

## 개발과 검증

검증에는 **Node.js 20 이상**이 필요합니다. 외부 npm 패키지를 사용하지 않아 `npm install`은 필요 없습니다.

```powershell
# 웹 원본 수정 후 GitHub Pages 게시본 갱신
npm run sync:pages

# 문법, 게시본 동기화, 회귀 테스트 검사
npm run check

# 회귀 테스트만 실행
npm test
```

테스트는 입력 파싱, 숫자·경로·RAW 매칭, 중복 후보·이름 충돌·중복 제거, ZIP 구조·내용·CRC·취소·제한, 폴더 선택의 클릭 활성화와 재선택, 원본·저장 폴더 동일 여부 및 핸들 누락·권한 오류, 폴더 선택 없는 파일별 다운로드·원본 내용 보존·이름 충돌·중복 제거·요청 실패·취소·URL 정리와 명시적 저장 위치 사용을 검증합니다. 파일 접근 권한과 실제 저장 대화상자는 브라우저에서 별도로 확인해야 합니다.

`sites/filecopier-web/dist/`가 원본이고 `docs/`는 GitHub Pages 게시본입니다. `docs/`를 직접 수정하지 마세요. 원본 수정 후 동기화하며 두 디렉터리가 다르면 `npm run check`가 실패합니다.

## 배포

### GitHub Pages · 기본 배포

`.github/workflows/pages.yml`이 `main` 브랜치의 push와 수동 실행을 처리합니다.

1. 웹 원본 `sites/filecopier-web/dist/`를 수정하고 `main`에 push합니다.
2. GitHub Actions가 게시본 동기화, 문법 검사와 회귀 테스트를 실행합니다.
3. 검증에 통과한 웹 원본만 배포합니다. 저장소 전체나 이전 데스크톱 코드는 사이트에 게시하지 않습니다.
4. https://lucky2449.github.io/selective-file-copier/ 주소가 갱신됩니다.

Pull Request에서는 검증만 실행하며 운영 사이트에는 배포하지 않습니다. 로컬 게시본을 직접 동기화하지 않았더라도 Actions가 배포 전에 생성합니다.

처음 설정할 때 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 지정합니다. GitHub Pages 사용이 허용되는 저장소·요금제여야 합니다. 배포에는 GitHub가 실행마다 제공하는 토큰을 사용하므로 별도의 API 키를 등록할 필요가 없습니다.

실행 상태는 [Actions](https://github.com/lucky2449/selective-file-copier/actions/workflows/pages.yml)에서 확인합니다. 검증 또는 배포가 실패하면 이전에 배포된 사이트가 유지됩니다.

### 기존 Sites 배포

기존 `chatgpt.site` 주소는 별도 배포입니다. GitHub Actions는 이 주소를 갱신하지 않습니다. 기존 배포 식별자는 `sites/filecopier-web/.openai/hosting.json`에 보존합니다.

폴더 복사의 쓰기 전·완료 직전에 대상 파일의 크기와 수정 시각 및 확인 가능한 원본 포함 관계를 검사합니다. 지원되는 브라우저에서는 독점 쓰기 모드를 요청합니다. 다만 브라우저 API에는 원자적인 독점 파일 생성 기능이 없고 다른 프로그램의 접근까지 잠그지 못하므로, 외부 프로그램의 동시 변경을 완전히 차단하지는 못합니다. 원본은 읽기만 하며 원본 핸들로 쓰기·삭제·이동·이름 변경을 호출하지 않습니다.
